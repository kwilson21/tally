## Goal

One command prints a side-by-side report of Jev, Clef and Clef-flash answering Tally's own call about the demo's transactions, so the owner can decide on decision 9 with numbers.

## What the docs say (checked 2026-10-19)

- **Models:** `@cf/cloudflare/clef` (27B) and `@cf/cloudflare/clef-flash` (9B), called with `env.AI.run(modelId, body, options)`. The body's `model` field is `"clef"` or `"clef-flash"`. The rest is the System One body Jev takes: `state`, plus `questions` with 1 to 64 entries of type `noul`, `choice` or `score` (developers.cloudflare.com/workers-ai/models/clef/).
- **Input schema** (developers.cloudflare.com/workers-ai/models/clef/schema-input.json):
  - A choice question's `criteria` maps option ids to descriptions, which may be `null`, with 2 to 255 options. Tally sends up to 51.
- **Output schema** (developers.cloudflare.com/workers-ai/models/clef/schema-output.json):
  - The result is `{ model, answers, usage }`, with no `result` wrapper.
  - A choice answer is `{ type: "choice", choice, probabilities, confidence }`, all required.
  - A noul answer is `{ type: "noul", noul }`.
  - `usage` is `{ input_tokens, output_tokens }`.

  Those are the field names Tally's parser reads (src/ai/categorize.ts:207-224), so the call should read as it is. The run confirms it.
- **Context and price:** the context window is 64K tokens for Clef and 24K for Clef-flash. Input costs $0.240 and $0.038 per million tokens, and output is free (Oct 9 changelog).
- **Local dev:** under `wrangler dev`, AI bindings always run remotely and are billed. Set `"remote": true` on the binding (developers.cloudflare.com/workers/development-testing/).
- **Types:** `Ai.run` has an overload for model ids missing from the generated list, taking `Record<string, unknown>` (worker-configuration.d.ts:10559). No cast is needed.

## Choices made here (internals, not the owner's)

- **A Worker of its own, never deployed:** `scripts/compare-models/worker.ts`, with its own `scripts/compare-models/wrangler.jsonc`:
  - `"$schema": "../../node_modules/wrangler/config-schema.json"`
  - `name: "tally-compare-models"`, `main: "worker.ts"`, `compatibility_date: "2026-09-22"`
  - `ai: { binding: "AI", remote: true }`
  - `secrets: { required: ["JEV_API_KEY"] }`, so the env file gives the Worker only that key, and Wrangler warns when it's missing (wrangler-dist/cli.js:185422-185438)
  - `workers_dev: false`, `preview_urls: false`
  - no D1, no assets, no routes, no crons.

  The app's wrangler.jsonc stays untouched, so `npm run dev`, the tests and CI never get an AI binding. The Worker has its own `type CompareEnv = { AI: Ai; JEV_API_KEY?: string }`, not the app's `Env`.
- **Tally's exact call:** every model is asked through `askJev` (src/ai/categorize.ts:60) with `{ details: true, people: [{ id: 1, name: "Everyone" }] }`, the person every household starts with (migrations/0030_transaction_details.sql:7, src/demo/reset.ts:112). That way the request, the parser and the 10-second timeout are the app's own, and the call carries the nine questions the nightly sort asks when every switch is on.
  - **Jev** gets `env.JEV_API_KEY` and the Worker's `fetch`.
  - **Clef and Clef-flash** each get a `fetchImpl` adapter, `viaWorkersAI(ai, modelId, selector)`. It parses the request body, sets `model` to the selector and awaits `ai.run(modelId, body, { signal: init?.signal })`, as src/ai/suggest-name.ts:56 passes its signal. It returns the result as a JSON `Response` with status 200. It doesn't catch a throw: `askJev` reports one as no response, as it does for a Jev timeout.
  - **A recording wrapper** sits around each model's `fetchImpl`. It keeps that model's first thrown error message, its first response body askJev couldn't read (a clone) and its first `usage`, then rethrows or returns unchanged.
  - **The parser stays as it is.** With `details: true`, a missing `kind` or `for_person` makes the whole answer unreadable (categorize.ts:241-242). That is a result too: the kept body shows what came back.
- **Cases (a new family's first sync):**
  - Start from `buildSeed(today)` (src/demo/seed.ts:438), skipping split parts (`parentId` set), split parents (`isSplit` true) and rows on the `cash` account. Plaid never sends a cash row.
  - There is one case per raw name and direction (money in or money out).
  - **The input** comes from the case's first row in `buildSeed`'s array order. `displayName` is that row's `merchantName` (Plaid's) or null, and `accountType` is its account's `type`.
  - Nothing else is sent: no `plaidCategory` (the demo's rows have none, which real rows do), no `merchantCategoryHistory`, note, kind or person. A new family has none yet.
  - **The right answer** is the first category any of the case's rows has, in array order, whatever its source. That makes APPLE.COM/BILL Household (seed.ts:283, :510-518).
  - Cases with no right answer are the rows the demo leaves for a person, plus the income, transfer and reimbursement rows. Each case also carries the seed's three flags, and they are the right answers for the flags.
- **`today`:** a parameter of `runComparison`, defaulting to `todayIn(DEFAULT_TIME_ZONE)` (src/dates.ts:20, :40), the demo's own zone. The demo's cases change with the day of the month (seed.ts:640-642), so tests pin `"2026-10-19"`.
- **Two category lists:**
  - **Demo:** the demo's 7 (`buildSeed(today).categories` in `sortOrder`).
  - **Fifty:** decision 37's most, made of three parts in this order:
    - the demo's 7
    - the 9 starting categories (migrations/0005_default_categories.sql:23-38) the demo doesn't have: Car & Transport, Utilities, Subscriptions, Shopping, Personal Care, Health, Entertainment, Date Night, Donations & Charity
    - these 34: Phone, Internet, Streaming, Gym, Doctor, Dentist, Pharmacy, Health Insurance, Car Insurance, Home Insurance, Car Payment, Car Repair, Parking, Tolls, Public Transit, Rideshare, Travel, Hotels, Flights, Clothing, Shoes, Gifts, Pets, Vet, Hobbies, Crafts, Books, Electronics, Home Repair, Garden, Furniture, Bank Fees, Taxes, Allowance.

    Some of these are fair answers too (Gym for CITY GYM MEMBERSHIP, which the demo calls Household). The report says so under the fifty-list tables.
- **Scoring is Tally's own:** each answer goes through `decide(answer, categories, JEV_THRESHOLD)` (src/ai/decide.ts:48, src/ai/categorize.ts:8). Category ids are each name's 1-based position in its list. So "applied" means exactly what Tally would store, 0.80 itself included (src/ai/confidence.ts:8).
- **One call at a time:** one model, one list and one case at a time, in order, with no retries. That is about 36 cases × 2 lists × 3 models, about 220 calls, and under $0.25 at the prices above.
- **Routes:**
  - `GET /` runs everything. `GET /?model=jev|clef|clef-flash&list=demo|fifty` runs one slice, in case a long request dies.
  - Any other path is a 404, so a browser's `/favicon.ico` never starts a second paid run.
  - The report comes back as `text/markdown`.
  - Each call logs one console line: model, list, case number, outcome and ms. No names or amounts (CLAUDE.md).

  The demo's data is invented and already public, so the report itself may show it. The Worker has no D1 binding, so it can't read anything else.

## Tasks (tests first, each one red before its code)

All tests go in `test/compare-models.test.ts`, which imports from `../scripts/compare-models/` as test/capture.test.ts:8 imports from `../scripts/`. Fake `AI` objects are cast `as unknown as Ai`, as test/scheduled.test.ts:76 does. Fake answers carry valid `kind` and `for_person` answers (`"person:1"` or `"none"`), or every fake call is unreadable.

1. **Cases:** `buildCases(seed)` in `scripts/compare-models/score.ts`.
   - **Test:** use a small hand-made `Seed` holding:
     - a split purchase with its two parts
     - a store seen three times
     - a refund of that store's purchase (money in)
     - a store with a Plaid `merchantName`
     - a store whose first row has no category and a later row does
     - a row with no category at all
     - a cash row
     - a transfer
   - **It gives:**
     - one case per raw name and direction
     - split and cash rows skipped
     - the input from the first row, and the right answer from the first category
     - `displayName` from `merchantName`, and `accountType` from the account
     - a null answer for the row with no category, and the flags as seeded
   - **Also:** `buildCases(buildSeed("2026-10-19"))` gives exactly the count you find on that date (the brief check counted 36), and every demo category is some case's answer.
2. **Category lists:** `demoCategories(seed)` and `fiftyCategories(seed)`.
   - **Test:** the fifty list has 50 different names. Its first 7 are the demo's, in `sortOrder`, and the next 9 are the starting categories named above.
3. **Scoring:** `scoreCase(kase, result, categories, ms)` returns one outcome.
   - `failed` is a failed call with a non-2xx status, or `no response` when the status is null.
   - `unreadable` is `ok: false` with a 2xx status (categorize.ts:191-193).
   - A case with a right answer is `right`, `wrong`, `left: none fit` or `left: unsure`. Left means `decide` applied nothing: `none fit` when `noneFit` is set, otherwise `unsure`.
   - A case without a right answer is `applied`, `left: none fit` or `left: unsure`.
   - Each flag is `hit`, `false alarm`, `missed` or `quiet`, comparing `decision.flags` with the seed's.
   - It also keeps the pick, its confidence, the ms, and whether the answer has `mixed` and `noteWorthWriting`.
   - **`summarize(rows)`** counts:
     - each outcome
     - "right pick at any confidence": the pick is the right answer, applied or not
     - "mixed and note answered"
     - the confidence's lowest, middle (median) and highest over the answered cases
     - the middle and slowest ms
   - **Tests:** use hand-made `JevResult`s for every outcome, including:
     - confidence exactly 0.80 (applied), and 0.7999 (unsure)
     - "None of these fit" at 0.95 (none fit)
     - the right pick at 0.70 (unsure, but counted in "right pick at any confidence")
     - `ok: false` with status 429, with status null, and with status 200 (unreadable).
4. **Report:** `formatReport(...)` in `scripts/compare-models/report.ts` returns markdown.
   - **A header** gives the date, the case count, whether Jev ran, "The demo's rows carry no Plaid category, which real rows do." and "Times are measured from this machine through wrangler dev."
   - **For each list, a summary table** with one row per model. Columns: calls that worked; right; right pick at any confidence; wrong; left (none fit / unsure); applied with no right answer; flags (hit / false alarm / missed); mixed and note answered; confidence (low / middle / high); middle and slowest ms.
   - **Then a per-case table:** raw name, direction, the demo's category, then each model's pick and confidence with ✓ on a pick Tally would apply, and the flags it would set.
   - **Under the fifty-list tables:** "Some of the 50 names fit these stores as well as the demo's own category does, so read the picks, not just the count."
   - **Then, for each model,** its first error message, first unreadable body (raw JSON) and first `usage`, when there was one.
   - Plain words throughout, because the owner reads it.
   - **Tests:** the header; the model rows; a ✓ on an applied pick; a failed call's status; the fifty-list line; a raw unreadable body and an error message, each appearing once.
5. **Worker:** in `scripts/compare-models/worker.ts`.
   - `runComparison(env, fetchImpl = fetch, today = todayIn(DEFAULT_TIME_ZONE), slice?)` asks each model in the slice over its lists and returns the report.
   - Without a `JEV_API_KEY`, or with an empty one, Jev's rows say "skipped: no JEV_API_KEY" and Clef still runs.
   - The default export's `fetch` serves the routes above.
   - **Tests** (a fake `AI` whose `run` records its arguments and returns a schema-shaped answer; Jev's fake `fetchImpl`):
     - Clef is called as `@cf/cloudflare/clef` with `model: "clef"`, Clef-flash likewise, and the third argument's `signal` is an `AbortSignal`.
     - On `"2026-10-19"`, each model gets exactly two calls per case (one per list).
     - A throwing `run` makes that model's rows "failed: no response", and its message appears once in the report.
     - A 200 the parser can't read shows as `unreadable`.
     - With no `JEV_API_KEY`, Jev is skipped.
     - Jev's `fetchImpl` gets `JEV_URL` with the bearer key.
     - `?model=clef&list=demo` makes only those calls.
     - `/favicon.ico` is a 404 that makes no call.
6. **Config, types and how to run it.**
   - Write `scripts/compare-models/wrangler.jsonc` as above.
   - Add `"../scripts/**/*.ts"` to test/tsconfig.json's `include` (today it has only `../scripts/**/*.mjs`), so `npm run typecheck` checks the new files.
   - At the top of worker.ts, write a comment of a few lines saying what it is and how to run it, so it's explainable in one plain sentence:

     The env file's path must be absolute, because Wrangler resolves it from the config's folder. The comment also says the Worker reads only `JEV_API_KEY`, needs `wrangler login`, bills Workers AI, and must never be deployed.
